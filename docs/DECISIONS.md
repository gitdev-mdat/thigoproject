# Architecture Decision Ledger

Only cross-cutting architecture decisions belong here. Product behavior and schema evolution do not.

| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------ |
| 2026-10-05 | Use a root pnpm workspace with Turborepo.                                                                                                                                                                                                                         | One repository and one command surface for independently deployable apps.                                                                                                                                                                                                                                                                     | Accepted                 |
| 2026-10-05 | Use Expo mobile, Next.js admin, and one NestJS API, all in TypeScript.                                                                                                                                                                                            | A consistent product language with platform-appropriate frameworks.                                                                                                                                                                                                                                                                           | Accepted                 |
| 2026-10-05 | Organize API code layer-first: Controller -> Service -> Repository -> Database.                                                                                                                                                                                   | Predictable dependency direction and traceability across features.                                                                                                                                                                                                                                                                            | Accepted                 |
| 2026-10-05 | Require all THIGO business data access through the NestJS API.                                                                                                                                                                                                    | Preserve one business authority and keep infrastructure replaceable.                                                                                                                                                                                                                                                                          | Accepted                 |
| 2026-10-05 | Use PostgreSQL as the relational source of truth; defer schema.                                                                                                                                                                                                   | Preserve database direction without freezing speculative product design.                                                                                                                                                                                                                                                                      | Accepted                 |
| 2026-10-05 | Keep CrewAI/9Router isolated as development infrastructure.                                                                                                                                                                                                       | AI availability must not affect product runtime.                                                                                                                                                                                                                                                                                              | Accepted                 |
| 2026-10-05 | Defer auth provider, queue, cache, object store, and realtime mechanism.                                                                                                                                                                                          | No current requirement justifies locking these choices.                                                                                                                                                                                                                                                                                       | Open                     |

| 2026-10-08 | Development fixtures (seeds, fixed test OTP, demo images) need `THIGO_ENABLE_DEV_FIXTURES=true` and `NODE_ENV` development or test; production refuses them.                                                                                                      | Secure by default: a missing or wrong setting can never expose demo data or the fixed OTP.                                                                                                                                                                                                                                                    | Accepted                 |
| 2026-10-08 | Store uploaded images as files on the API host (`MEDIA_STORAGE_DIR`) with metadata in `media_assets`, served through `GET /media/:id`. Only `MediaFileStore` touches the files.                                                                                   | Approved for local development and a single-instance MVP on a persistent, backed-up volume. Production refuses to start without `MEDIA_STORAGE_DIR` or with an unwritable one. Ephemeral or serverless disks are not safe. Moving to S3-compatible storage for several instances replaces only `MediaFileStore`; see `docs/MEDIA_STORAGE.md`. | Accepted with conditions |
| 2026-10-08 | A merchant publishes their own storefront, without Admin approval, once it has a valid phone, a valid address and at least one available product in a visible category. Images are optional; opening hours and "accepting orders" stay separate from publication. | Owner decision for F02. The API decides availability and checkout eligibility. Seeded stores already published without a phone stay published and show a missing-information warning; nothing is unpublished or given an invented phone.                                                                                                      | Accepted                 |

The future design is in `docs/proposals/PRODUCT_OPTIONS.md`.                                                                                                                                                                                                                                          | Deferred                 |
