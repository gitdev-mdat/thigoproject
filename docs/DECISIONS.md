# Architecture Decision Ledger

| 2026-10-05 | Use TypeORM with NestJS and `pg`; require migrations and disable synchronization.                                                                                                                                                                                                                                                                                                         | Establish one provider-neutral, production-safe PostgreSQL persistence path.                                                                                                                                                                                                                                                                  | Accepted                 |
| 2026-10-08 | Development fixtures (seeds, fixed test OTP, demo images) need `THIGO_ENABLE_DEV_FIXTURES=true` and `NODE_ENV` development or test; production refuses them.                                                                                                                                                                                                                              | Secure by default: a missing or wrong setting can never expose demo data or the fixed OTP.                                                                                                                                                                                                                                                    | Accepted                 |
| 2026-10-08 | Store uploaded images as files on the API host (`MEDIA_STORAGE_DIR`) with metadata in `media_assets`, served through `GET /media/:id`. Production refuses to start without `MEDIA_STORAGE_DIR` or with an unwritable one. Ephemeral or serverless disks are not safe. Moving to S3-compatible storage for several instances replaces only `MediaFileStore`; see `docs/MEDIA_STORAGE.md`. | Accepted with conditions |
| 2026-10-08 | A merchant publishes their own storefront, without Admin approval, once it has a valid phone, a valid address and at least one available product in a visible category. The API decides availability and checkout eligibility. Seeded stores already published without a phone stay published and show a missing-information warning; nothing is unpublished or given an invented phone.                                                                                                      | Accepted                 |
| 2026-10-08 | Merchant-managed product options are deferred beyond F02; options stay seed-only and checkout keeps validating them.                                                                                                                                                                                                                                                                      | F02 avoids a topping or variant engine. | 2026-10-08 | Merchant accounts stay provisioned under the F01 identity model; F02 adds storefront onboarding only, never self-registration.                                                                                                                                                                                                                                                            | Account provisioning (who may sign in as a merchant) and storefront onboarding (what a signed-in merchant sets up) are separate concerns.                                                                                                                                                                                                     | Accepted                 |
| 2026-10-09 | Local development uses the Docker PostgreSQL in `compose.yaml`. | 2026-10-09 | DEV quick login lists seeded accounts from `GET /auth/dev/quick-login` only with development fixtures and the test OTP on, then signs in through the normal OTP endpoints.
